- **webapp-login: forget an add that never left** (2026-10-29, #17): `SignIn.startAdding` sets `tp-login-adding` (and the step-up tenant) in sessionStorage before the redirect, and nothing clears it if the redirect fails. Since #17 the page stays put with an inline error after a failed redirect. If the person then signs out and signs in again in the same tab, `complete()` treats that fresh sign-in as an add. Fix: in `startAdding`, clear both keys when `start` throws (bug-sized; flow.ts).
- **Unmaintained crates `cargo audit` still warns about** (2026-10-30, #20): after the aws-lc-rs relock there are no vulnerabilities, but four unmaintained warnings remain: `backoff` 0.4 and its `instant` (RUSTSEC-2025-0012, RUSTSEC-2024-0384; via the generated `httpclient` chassis), `serde_yaml` 0.9's `unsafe-libyaml` (RUSTSEC-2024-0449; via the generated types crate) and `rustls-pemfile` 2 (RUSTSEC-2025-0134; via `axum-server`, the generated model and the gateway itself). The first two belong upstream in tacplus' Rust chassis; `rustls-pemfile` the gateway can drop by parsing PEM with `rustls-pki-types`' `PemObject`. Since 2026-10-01 a fifth: `pin-utils` 0.1.0 (RUSTSEC-2026-0441), whose only path in is `hyper` 1.8.1 (`cargo tree -i pin-utils`); `hyper` 1.12.0 no longer depends on it, so a lockfile-only `cargo update -p hyper` should clear it (nightly scan, 2026-11-05). The build's security checks now report all five as new findings: tracked as the bug #31 (nightly scan, 2026-11-11).
- **Unused `EnvFilter` import in main.rs** (2026-10-30, #20): every build warns `unused import: tracing_subscriber::EnvFilter` (src/main.rs:50). Remove it.
- **One shared harness for the end-to-end tests** (2026-11-03, #23): `e2e_user_mint.rs`, `e2e_form_post.rs` and `e2e_mint_trace.rs` each carry their own copy of `unused_verifier()`, the plaintext `ProxyState` wiring and a "serve this stand-in on a real port" helper. A `#[cfg(test)] mod e2e_harness` holding them would cut ~40 lines a file and make the next stand-in (each trace-propagation test needs one, looper#51) a few lines. Not done in #23 so as not to collide with #24, which reworks `e2e_user_mint.rs`'s harness. Since #24, `e2e_stream_trace.rs` is a fourth copy, and it and `e2e_user_mint.rs` each define the same do-nothing `KernelMinter` (`NoMinter`) to build a REST router.
- **A REST `GET` cannot carry a trace_id** (2026-11-03, #24): `rest_translation::read_body_for_method` forwards `{}` for every `GET`, and query parameters are not mapped, so any RPC called by `GET` on its REST route (the streaming routes allow `GET` too) always reaches the backend with an empty `trace_id`; only a `POST` body can set it. Mapping a `traceId` query parameter (or an inbound trace header) onto field 200 would let browser `GET`s be traced. New behaviour: a `feature`, needs design.
- **MCP session frames have no trace_id** (2026-11-03, #24): `sys.mcp.McpRequest` (every `Broker*McpSession` route the gateway proxies) declares no field 200, so no MCP session through the gateway can be traced, and none could be covered by #24's WebSocket test (it uses `oauth.Session/BrokerSession`, whose `SessionRequest` has one). The message is tacplus' (`sys/mcp.proto`), so the change is there.
- **Drop the ROADMAP "Later" item "Keep the Let's Encrypt certificate across a kernel restart"** (2026-11-03, #25): the gateway no longer reads LetsEncryptState at all; its certificate is in its own config, delivered by kernel's system-config refresh and put there by the deployment's pipeline (tacplus-dev/roadmap:decisions/certificates-by-pipeline-2026-11-03.md), so there is nothing of letsencrypt's left to keep. Jody's file, so only a proposal here.
- **One certificate for every hostname now** (2026-11-03, #25): letsencrypt mode served a certificate per hostname by SNI; `cert_chain` serves one chain to every name, so `external_cert_pem` has to cover each `external_hostnames` and `web_bundles` hostname (the decision's wildcard plus apex does). Nothing checks that coverage at load; a check that refuses (or warns about) a certificate missing one of `external_hostnames` would catch a wrong secret version before browsers do. New behaviour: a `feature`, needs design.
- **ROADMAP "Now": the floor in force** (2026-11-07, #28): #28 asks for ROADMAP.md's "Now" line to name the floor in force, and a looper's commit touching ROADMAP.md is refused. The line, for an agent at Jody's request: "Unreleased; tacplus floor 2.6 (2.6.1 pinned in tacplus.lock, #28)."
- **Scan the shipped image, not only Cargo.lock** (2026-11-12, #33): the build's security checks cover `Cargo.lock` and the Dockerfiles' SAST, but nothing scans what the image actually ships besides the gateway: the `grpc_health_probe` binary copied from `ghcr.io/grpc-ecosystem/grpc-health-probe` (#11 and #33 were both found only by the nightly scan running `govulncheck -mode binary` on it by hand) and the `debian:trixie-slim` base. An image scan (or a `govulncheck -mode binary` step on the probe) in the build pipeline would catch the next one at build time; gateway's image is built per fleet, so it belongs in tacplus-dev/build. Since #33 the probe is pinned by digest, so a bump is a deliberate two-field change (tag and digest) in both Dockerfiles.
